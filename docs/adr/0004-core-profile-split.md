# ADR-0004: 스택 무관 기능은 `core/`, 스택 종속 기능은 `profiles/`로 나눈다

| 항목 | 값 |
|---|---|
| 상태 | 채택 |
| 결정일 | 2026-09-29 |
| 결정자 | 박시현 |
| 관련 | roadmap M3, 원칙 "일반화를 미리 하지 않는다" |

## 맥락

다음 프로젝트의 스택은 아직 정해지지 않았다. feelm은 Spring Boot Java와 React TypeScript였고, 기업
요구 명세에는 Kotlin과 Vue가 보인다. 템플릿·hooks·보안 CI·측정은 스택과 무관하지만 Scaffold와
컨벤션 테스트는 스택마다 다르다.

## 결정

`core/`에는 스택과 무관한 것만 둔다: 규칙 템플릿, hooks, CI 조각, 측정. `profiles/<name>/`에는 스택
종속인 것만 둔다: Scaffold, 컨벤션 테스트, 검증 명령 정의. 처음엔 `spring-java`와 `react-ts` 두 프로필만
만들고, 다른 스택은 다음 프로젝트 스택이 정해진 뒤 추가한다. `core/`가 특정 스택을 가정하기 시작하면
그 부분은 프로필로 내린다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A (선택) core / profiles 분리 | 스택 변경 시 프로필만 추가, core 안정 | 프로필 인터페이스 정의 필요 |
| B 단일 스택 키트 | 단순 | 다음 프로젝트 스택이 다르면 대부분을 다시 씀 |
| C 처음부터 4개 스택 지원 | 즉시 대응 | 검증 안 된 프로필이 쌓임, 과잉 일반화 |

## 결과

- **얻는 것**: 스택 결정을 기다리지 않고 core를 진행
- **감수하는 것**: 프로필 인터페이스(정의 파일, scaffold 명령 규약)를 M3 초입에 확정해야 함
- **후속 작업**: M3-1 프로필 구조 확정
- **후속(2026-10-03, M3-1)**: 프로필 정의 파일 이름은 `verify.json`이 아니라 `profile.json`으로 정했다. 검증 명령 외에 판정 기본값·변수·스캐폴드·컨벤션 파일·계층 규칙 기본값을 담기 때문이다. 결과의 `verify.json` 표기는 이 결정으로 읽는다
