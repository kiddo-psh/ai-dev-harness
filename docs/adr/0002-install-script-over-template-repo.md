# ADR-0002: 배포는 GitHub 템플릿 저장소가 아니라 설치 스크립트로 한다

| 항목 | 값 |
|---|---|
| 상태 | 채택 |
| 결정일 | 2026-09-29 |
| 결정자 | 박시현 |
| 관련 | roadmap M1-3, 백로그 `harness update` |

## 맥락

키트는 두 상황에서 쓰인다. 새 저장소를 만들 때와 이미 코드가 있는 저장소에 붙일 때. 다음 프로젝트는
SSAFY GitLab에서 돌므로 GitHub 쪽 기능(템플릿 저장소, 재사용 workflow)에 의존할 수 없다. 키트가
갱신되면 이미 적용한 저장소에 변경을 전파할 방법도 필요하다.

## 결정

`bin/harness.py init <target>`이 대상 저장소에 파일을 생성하고 `harness.json`에 설정과 키트 버전을
기록한다. `check`가 렌더링 결과와 실제 파일의 차이를 보고한다. 갱신 전파는 백로그의 `update`
명령으로 다룬다. 스크립트는 표준 라이브러리만 사용해 어떤 환경에서도 `python` 하나로 실행된다.

## 고려한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A (선택) 설치 스크립트 | 새·기존 저장소 모두 지원, 플랫폼 무관, 버전 기록 가능 | 스크립트 유지 비용 |
| B GitHub 템플릿 저장소 | 클릭 한 번 | 새 저장소에만 가능, GitLab 불가, 갱신 전파 없음 |
| C git subtree / submodule | 갱신이 git으로 됨 | 규칙 파일은 루트에 있어야 하는데 subtree는 하위 경로에 놓임, 자리표시자 치환 불가 |

## 결과

- **얻는 것**: 어떤 저장소에도 반나절 안에 적용, 드리프트 검사로 규칙 파일의 단일 원천 유지
- **감수하는 것**: 템플릿 자리표시자 체계를 유지해야 함
- **후속 작업**: `update` 명령, 영역 AGENTS.md 생성(`init --area`)
