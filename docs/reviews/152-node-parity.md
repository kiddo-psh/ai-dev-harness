## 3. 발견 사항

### F1 — `.gitlab-ci.yml`의 `services`·스크립트 줄 `node:<ver>`도 고정 버전으로 읽는다
- 단위 / 관점: U1 / 정확성
- 근거: `_CI_NODE`가 키를 가리지 않는다. `docker run node:18 ...` 같은 스크립트 줄이 있으면 불일치로 실패한다.
- 영향과 제안: 낮음. YAML 파서 없이 키를 구분하면 오히려 `image: {name: ...}` 형태를 놓친다. 한계로 문서화했고 `HARNESS_VERIFY_PARITY=off`로 끌 수 있다.

### F2 — `engines` 상한 규칙은 라이브러리 패키지에서 오탐이 날 수 있다
- 단위 / 관점: U1 / 계약 정합성
- 근거: 배포용 라이브러리는 `engines`를 일부러 넓게 둔다. 영역이 라이브러리이고 Dockerfile·CI 이미지 고정이 있으면 실패한다.
- 영향과 제안: 참고. 키트 대상은 앱 저장소이고, feelm 사례를 CI에서 결정적으로 잡는 유일한 규칙이다. 첫 적용에서 오탐이 나면 friction 이슈로 받는다.
