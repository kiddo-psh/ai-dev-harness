## 3. 발견 사항

최초 W1에서는 재현 가능한 결함을 발견하지 못했다. 이후 CI에서 아래 두 검증 누락이 확인되어 수정했다.

### F1 — 새 hook·스모크 파일 판정 목록 누락
- 단위 / 관점: U2·U4 / 테스트 실효성.
- 근거: CI `KitSelfJudgeTest.test_new_files_in_watched_dirs_need_a_decision`에서 새 파일 4개가 EXPECTED에 없어 실패했다. 최초 로컬 검증은 Git 추적 전 새 파일을 조회하지 못했다.
- 영향과 제안: 네 파일을 기존 표준 정책으로 명시하고 생성 Codex hook의 표준 경로 규칙을 추가했다. 목록 검사도 untracked 파일을 포함해 커밋 전에 같은 누락을 잡도록 강화했다.

### F2 — 재시도 통합 테스트가 v1 요청 한 번만 가정
- 단위 / 관점: U1·U4 / 정확성·테스트 실효성.
- 근거: v1 실패 후 v2 exporter도 시도하므로 요청 수는 2회다. `attempts == 1`의 순간을 놓치면 CI에서 20초 기다린 뒤 실패했다.
- 영향과 제안: v1 상태 및 v2 실패 상태 저장 완료를 기다린 후 요청 2회와 복구 시 exporter의 이전 실패 수를 검사한다. 제한 시간을 늘리거나 assertion을 제거하지 않았다.

로컬 미실행 통합 스모크와 실제 Codex 환경별 hook 동작은
검증 한계로 남긴다. 문서는 `codex exec` hook 미실행과 다른 실행 환경 미확인을 명시한다.

조건부 관점: 동시성·트랜잭션 열림. v1/v2 상태 분리, v2 파일 잠금 아래 outbox 저장,
네트워크 전 저장·성공 묶음 표시·부분 거절 재시도와 고정 ID를 대조했다. hook의 간격 표시는
전송 중복 방지 잠금이 아니며 실제 중복 처리는 push와 중앙 ID 집계가 담당한다.
인가 닫힘: 기존 endpoint·사용자 자격 파일 해석 경로를 재사용하며 새 권한 경계는 추가하지 않는다.
